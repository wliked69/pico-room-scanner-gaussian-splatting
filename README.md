# PICO Room Scanner & Gaussian Splatting

使用 PICO 头显拍摄房间，在 Windows 电脑上完成高斯泼溅重建、模型查看和近似碰撞网格导出。

## 下载

进入 [Releases 下载页](https://github.com/wliked69/pico-room-scanner-gaussian-splatting/releases/latest)，下载：

| 文件 | 用途 |
| --- | --- |
| `RoomSplat-efficient-depth-v32r1.apk` | 安装到 PICO 头显的扫描软件 |
| `RoomSplat-Windows-20261022.zip` | Windows 便携建模软件，完整解压后运行 |
| `SHA256SUMS.txt` | 两个安装文件的 SHA256 校验值 |

GitHub 自动生成的 `Source code` 是开发源码，不是 Windows 可直接运行的程序。安装包不含个人房间照片、扫描数据包或模型。

## 1. 准备设备

- 使用支持本项目相机和空间数据能力的 PICO OS 6 头显。项目使用 Spatial SDK/BOM 6.1.9，Android 最低版本为 API35；其他 PICO 型号是否具备所需能力，应以应用的能力检查为准。
- Windows 电脑与可传输数据的 USB 线。打开头显开发者模式和 USB 调试，首次连接时在头显内允许这台电脑调试。
- 建模软件可以选择 NVIDIA、AMD 或 Intel 显卡，显卡和驱动需要支持 Brush 引擎所需的 WebGPU/Vulkan 功能。CPU 用于相机求解及碰撞网格阶段，高斯训练使用 GPU，没有自动改用 CPU 训练的选项。
- 电脑和头显留出保存照片、扫描 ZIP、重建中间文件和模型的空间。重建中间文件会使占用大于原始扫描 ZIP。

## 2. 安装扫描软件

1. 下载 Releases 中的 APK，通过你使用的 PICO APK 安装工具安装到头显。
2. 已有同签名的 RoomSplat 时覆盖安装；需要保留扫描时，不要先卸载或清除应用数据。
3. 在头显应用列表打开 **RoomSplat**，戴好头显并保持唤醒，按系统提示允许**相机**和**空间数据**权限。
4. 若面板提示采集未就绪，点击 **“授予权限 / 重新检查”**。能看到蓝色覆盖网格后再开始拍照。

如果电脑已安装 pico-cli，也可以在 APK 所在目录打开 PowerShell：

```powershell
pico-cli device list
# 把 DEVICE_SERIAL 替换为上一步列出的头显序列号。
pico-cli app install ".\RoomSplat-efficient-depth-v32r1.apk" --replace -d DEVICE_SERIAL
pico-cli app launch com.example.roomsplat --activity .platform.LaunchActivity -d DEVICE_SERIAL
```

出现 `unauthorized` 时，在头显内允许 USB 调试；仅打开调试开关，还不等于已授权电脑。如果更新提示签名冲突，先导出并备份重要扫描，再处理安装来源和签名问题。

## 3. 扫描房间并打包

### 开始采集

1. 打开室内照明。先看清扫描面板，抬起左手可操作跟手面板。
2. 点击 **“开始采集”**，确认 **“已保存照片”** 数字增加。
3. 缓慢绕房间移动，让同一面墙或家具从多个站位出现在相邻画面里。保留画面重叠，不要只站在原地快速转头。
4. 遇到墙角、门边和家具侧面时，从不同方向补拍。纯白墙、玻璃、镜面、重复纹理和运动物体会使图像匹配更困难。

### 看懂覆盖提示

| 颜色或数字 | 含义 |
| --- | --- |
| 蓝色 | 已发现、尚待拍摄的区域 |
| 黄色 | 已记录照片，仍需要补拍 |
| 绿色 | 已记录两个不同站位的照片 |
| 已保存照片 | 实际写入的照片数量 |
| 已发现区域已拍过 / 多站位 | 按区域去重的拍摄覆盖提示 |

覆盖颜色用于指导采集；绿色不等于重建一定成功，也不是精度认证。**“覆盖参考”**开关只控制提示网格显示，不删除照片或数据。

### 暂停、结束与打包

1. 临时停下时点 **“暂停”**，需要继续时点 **“继续采集”**。
2. 扫描结束后点 **“完成采集” → “结束采集”**。
3. 点击 **“打包数据”**，等待面板显示 **“数据包已保存”**。照片不足时会提示继续采集。
4. 保留该扫描 ZIP，按下面的导入步骤传到电脑。

### 换房间或重新扫描

需要清除当前扫描时，点 **“重置扫描数据” → “确认重置”**；打包完成后也可用 **“扫描另一个房间”**开始下一次采集。重置会清除当前原始照片及应用网格/覆盖记录，保留已打包 ZIP。先确认需要保留的数据已打包并传到电脑。

应用重置不会删除系统共享空间地图。出现的网格属于覆盖参考，不能把它当作已经生成的高斯模型。

## 4. 安装电脑建模软件

1. 下载 `RoomSplat-Windows-20261022.zip`。
2. **完整解压**，打开里面的 `RoomSplat` 文件夹，运行 **`RoomSplat.exe`**。
3. 保留同目录的 `_internal`、`tools` 等文件，不要只复制或移动 EXE，也不要直接在压缩包中运行。
4. 查看 **“COLMAP 程序”**与 **“Brush 程序”**路径。便携包包含所需引擎，通常会自动发现；若整个文件夹移动后找不到，可点对应的 **“选择…”**重新定位：
   - COLMAP：`tools` 下的 `colmap-worker.exe`。
   - Brush：`tools` 子目录中的 `brush_app.exe`。

便携包可以直接运行，不需要另装 Python 或 CUDA Toolkit。显卡驱动仍需满足训练引擎要求。

## 5. 从头显导入扫描

### 方式一：直接识别头显

1. USB 连接头显，保持唤醒并允许调试。
2. 在 Windows 程序点击 **“头显数据 · 导入 / 管理”**。
3. 有多台设备时选对设备，点击 **“刷新”**。
4. 选择 **“已打包 ZIP”**，在列表中选中要重建的扫描。
5. 可先点 **“查看照片 / 详情”**，用上一张/下一张检查照片是否清楚、明亮且覆盖目标房间。
6. 点击 **“传输并导入”**，选择电脑保存位置。软件会传输、校验数据，并选中导入后的采集项目。

### 方式二：导入没有打包的原始照片

在相同管理窗口中切换到 **“原始照片（含未打包扫描）”**，选择扫描，再点 **“传输并导入”**。至少需要 3 张照片才能作为导入项目；最低数量不代表足够完成整屋重建。

### 方式三：手动导入已复制的文件

- 已将扫描 ZIP 保存到电脑：点 **“导入扫描 ZIP”**，选择 ZIP 和保存位置。
- 已经导入过：点 **“打开已有采集目录”**，选择包含 `manifest.json` 与照片的采集目录，不是选择高斯 PLY 所在目录。

导入后查看软件里的照片数量及项目路径，再开始重建。

## 6. 运行重建

1. 在 **“训练显卡”**选择自动，或指定 NVIDIA、AMD、Intel。
2. 设置 **“训练步数”**，默认 7000。增加步数会延长训练；它不能弥补缺少相邻视角或严重模糊的照片。
3. 一般先保持 **“全量匹配”**关闭。若相机求解时照片分组断开较多，可尝试勾选后重跑，匹配耗时会增加。
4. 需要 Unity 等软件使用的碰撞网格时，勾选 **“同时导出碰撞网格（OBJ）”**，选择快速、标准或精细。
5. 点 **“开始重建”**，查看日志。流程包括图像特征与匹配、相机位姿求解、训练数据准备、GPU 高斯训练，以及可选的 CPU 网格生成。
6. 完成后软件显示模型路径。任务进行中可以点 **“取消重建”**；采集数据会保留，重新开始会创建新的重建目录。

**CPU 和 GPU 的分工：**相机求解时 CPU 工作、GPU 空闲是正常的；进入高斯训练后，`training.log` 及 `report.json` 会记录实际选择的显卡。不能仅凭某个阶段的总占用判断是否启用了 GPU。

## 7. 查找和查看模型

输出保存在导入采集目录的旁边，每次重建新建一个 `reconstruction-日期时间` 文件夹：

```text
你选择的项目保存位置/
├─ 采集目录/
│  ├─ manifest.json
│  └─ images/…
└─ reconstruction-日期时间/
   ├─ models/
   │  ├─ *.ply
   │  └─ collision-日期时间-…/
   │     ├─ collision.obj
   │     ├─ collision-report.json
   │     └─ Unity使用说明.txt
   ├─ report.json
   ├─ pipeline.log
   └─ training.log
```

- **查看高斯模型：**点 **“查看模型”**，由 Brush 查看器打开本次生成的 PLY。没有本次结果时会弹出文件选择框，可打开已有 PLY。普通三角网格软件未必能正确显示高斯 PLY。
- **定位文件：**点 **“打开项目文件夹”**。有模型结果时打开 `models` 文件夹；重建未完成时打开采集目录或程序目录。
- **查看准确路径：**日志中的 **“模型完成：……”**和 `report.json` 的 `result` 字段。
- **备份：**保留原始扫描 ZIP、完整采集项目和需要的模型输出。只复制 PLY 可以保留高斯模型，但不能保留用于重新训练的原始照片。

## 8. 导出碰撞网格并用于 Unity

### 自动或单独生成

重建时勾选 **“同时导出碰撞网格（OBJ）”**即可自动生成。也可以点 **“生成碰撞网格…”**，选择已有高斯 PLY，单独生成 OBJ。网格失败不会删除已经生成的 PLY，可以调整后重试。

点 **“预览碰撞网格…”**选择 OBJ，或在自动生成后查看预览窗口：

| 操作 | 效果 |
| --- | --- |
| 左键拖动 | 旋转 |
| 右键拖动 | 平移 |
| 滚轮 | 缩放 |
| R 或“恢复视角” | 复位 |
| “线框” | 检查三角形 |
| “剖开前侧” | 辅助观察内部 |

预览会简化显示，不修改导出的 OBJ。

### Unity 使用

1. 将 `collision.obj` 拖入 Unity 的 `Assets`。
2. 将导入的网格放到场景中，添加 **MeshCollider**，Mesh 选择该碰撞网格。
3. 用作静态房间碰撞时保持 **Convex 关闭**，不要把非凸房间网格挂到普通动态 Rigidbody 上。
4. 与高斯渲染对象使用一致的位置、旋转、比例。若使用的高斯渲染器翻转坐标轴，碰撞网格也需应用相同变换。
5. 在场景中检查墙、地面、门口及家具区域，再用于实际交互。

OBJ 是根据高斯估算的近似外壳；原始扫描未完成绝对米制标定，使用前需检查比例、孔洞与边缘。它不能作为真实环境的安全边界或精密测量结果。

## 9. 管理和删除扫描数据

在 **“头显数据 · 导入 / 管理”**中操作：

| 操作 | 删除范围 | 保留内容 |
| --- | --- | --- |
| 已打包 ZIP →“删除头显数据包” | 选中的头显 ZIP | 头显原始照片、电脑项目 |
| 原始照片 →“删除这张原始照片” | 当前照片，先按提示备份整次扫描 | 已打包 ZIP、电脑已有项目 |
| 原始照片 →“删除整次原始扫描” | 选中的原始扫描，先备份并校验 | 已打包 ZIP、电脑已有项目 |
| 原始照片 →“直接删除（不备份）” | 选中的原始扫描照片及网格数据，不创建备份 | 已打包 ZIP、电脑已有项目 |

删除原始照片前先暂停采集。软件会提示关闭头显扫描应用，并要求确认目标设备和扫描；备份式删除需要选择电脑备份位置。**直接删除不可恢复**，只在确定不需要原始照片时使用。

电脑上的采集项目和重建文件夹独立保存；删除头显数据不会自动清理电脑模型。按需通过资源管理器管理电脑副本。GitHub 仓库和 Releases 不会接收你的扫描文件。

## 10. 常见问题

| 问题 | 检查步骤 |
| --- | --- |
| 电脑找不到头显 | 检查 USB 是否支持数据；唤醒头显；确认开发者模式和 USB 调试；戴上头显允许该电脑调试后刷新 |
| 采集未就绪 / 相机不可用 | 戴好并唤醒头显，允许相机及空间数据权限，点“授予权限 / 重新检查” |
| 只有蓝色、不出现黄色 | 确认已开始采集、照片数增加；检查光照；暂停后继续；只显示网格并不等于正在拍照 |
| 绿色很少 | 围绕同一物体换站位补拍，不要只原地转头；绿色依赖不同站位的已保存照片 |
| 打包失败 | 查看头显面板错误，检查照片数量和可用空间，保留原始扫描后重试；也可从电脑直接导入未打包照片 |
| 相机求解失败 / 无有效3D模型 | 查看 `pipeline.log`；检查照片重叠、模糊和曝光，避免纯白墙或快速转头，补拍或重新采集；必要时尝试全量匹配 |
| GPU没有工作 | 先确认是否仍在CPU相机求解阶段；到训练阶段检查 `training.log` 的适配器记录及“训练显卡”设置 |
| 显卡不可用 / 显存不足 | 检查显卡驱动、程序选择的厂商及日志；关闭其他占显存程序；减少本次输入规模后重试；软件不会静默改为CPU训练 |
| EXE找不到依赖 / 启动失败 | 完整解压 Windows ZIP，保留整个文件夹，检查 `_internal` 与 `tools`，不要在ZIP内运行 |
| 看不到模型 | 用“查看模型”打开正确的高斯PLY，检查文件是否完整；OBJ请用“预览碰撞网格…” |
| 碰撞网格生成失败 | 保留PLY，查看日志，使用“生成碰撞网格…”单独重试并检查质量设置 |

提交问题时可描述复现步骤和报错文字；若附日志，请先移除不希望公开的路径、设备信息或房间内容，不必上传私人扫描。

## 11. 从源码运行与构建

### 源码目录

| 目录 | 用途 |
| --- | --- |
| `headset/` | PICO 房间扫描 Android 项目 |
| `desktop/` | Windows 建模、扫描管理与预览源码 |
| `tools/` | 引擎下载、Windows 构建与传输脚本 |

### 扫描端

使用 Android Studio 打开 `headset/`，准备 JDK21、Android SDK35、NDK28.2.13676358、CMake3.22.1。SDK/BOM6.1.9 由 Gradle 配置管理，自行配置本机 SDK 路径。

```powershell
cd headset
.\gradlew.bat --no-daemon assembleDebug testDebugUnitTest
```

输出：`app/build/outputs/apk/debug/app-debug.apk`。本机重新构建的调试签名可能与 Releases 安装包不同，覆盖安装前先核对签名和数据保留方式。

### Windows 源码运行

建议使用 Python3.12，在仓库根目录执行：

```powershell
python -m pip install -r desktop/requirements-build.txt -r desktop/requirements-mesh.txt
python tools/install_engines.py
cd desktop
python launch.py
```

`install_engines.py` 从官方发行版下载引擎，需要网络。源码依赖不会附带本机配置或已下载引擎；程序内可选择你安装的 COLMAP 与 Brush 路径。

运行 Windows 测试：

```powershell
cd desktop
python -m unittest discover -s tests -v
```

打包 Windows 便携程序，在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_windows.ps1 -PythonExe python
```

生成 `desktop/dist/RoomSplat/RoomSplat.exe`，分发时保留整个文件夹。

## 数据与依赖

仓库不包含私人照片、扫描 ZIP、PLY/OBJ、真实墙面几何/深度夹具、诊断日志、本机设置或签名私钥。原真实数据夹具相关测试未公开，内联真实深度样例已换为合成数值。内置 `box.usdz` 是通用程序资源，不是房间扫描模型。`.gitignore` 排除了常见数据输出；推送前仍应检查暂存列表。

第三方依赖适用各自授权与使用要求：[PICO Spatial SDK](https://developer.picoxr.com/)、[COLMAP](https://github.com/colmap/colmap)、[pycolmap](https://github.com/colmap/pycolmap)、[Brush](https://github.com/ArthurBrussee/brush)。本仓库暂未选择额外开源许可证。
